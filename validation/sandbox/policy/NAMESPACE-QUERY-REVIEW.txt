Source:
- kernel/nstree.c listns -> may_list_ns admits current namespaces. Its broad
  visibility alternative calls may_see_all_namespaces; filtering by an owning
  user namespace does not automatically grant visibility over all its namespaces.
- kernel/nscommon.c may_see_all_namespaces requires BOTH initial PID namespace
  membership and CAP_SYS_ADMIN in its user namespace. Mapped namespace root in
  the private command PID namespace does not meet that condition.
- fs/nsfs.c may_use_nsfs_ioctl requires that same permission for NS_MNT_GET_NEXT
  and NS_MNT_GET_PREV before adjacent namespace lookup/opening a returned FD.
  NS_MNT_GET_INFO and NS_GET_ID provide metadata for an already-open namespace FD.
- include/uapi/linux/nsfs.h supplies the retained structure sizes/ioctl numbers.

Runtime: two successive restricted command namespaces
-----------------------------------------------------
Open only /proc/self/ns/{mnt,pid,net,user,ipc,uts,cgroup,time}. Query each handle's
NS_GET_ID, then close it. On the own mount-namespace FD, NS_MNT_GET_INFO succeeds
and reports that same ID and a nonzero mount count. Well-formed NEXT and PREV
requests both return EPERM; no neighboring namespace FD is acquired or used.

Three bounded listns requests each use a 32-entry buffer and no pagination:
1. Unfiltered result exactly equals the set of eight current namespace IDs.
2. Mount-only result is exactly the current mount namespace ID.
3. Current-user-owned filtering produces a subset of current IDs including the
   current mount namespace. A current namespace need not be owned by the current
   user namespace, so this subset is deliberately not required to equal all eight.
Duplicate IDs, overflow/full buffer, missing expected IDs or unexpected IDs fail.
No numeric ID is used to request or enter an outside namespace. The tests do not
print the IDs, perform namespace mutation or send traffic.

The current cgroup/time namespaces can be inherited rather than private. Their
presence among current IDs is not proof they are dedicated to the command, nor
an assertion that every global namespace identifier is confidential. Conversely,
read-only metadata success is not permission to switch namespace or obtain an
adjacent namespace handle. Existing setns/unshare/clone restrictions remain.

Limits and consequence
----------------------
These kernel-enforced boundaries hold for the tested topology and credential
state; the candidate has no generic ioctl filter and allows listns. No additional
restriction is justified solely because these owned/current queries succeeded.
This is not exhaustive nsfs permission/ABI review, mount-ID statmount/listmount
qualification, exported file-handle acquisition review, or final-executor proof.
Trust in the VM kernel remains an explicit prerequisite. Source/test evidence
narrows the pending areas1/4/7 interface review without declaring it complete.
