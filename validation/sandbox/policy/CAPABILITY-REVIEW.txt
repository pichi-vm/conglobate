Retained capability review — 2026-10-21
======================================
Scope: diagnostic entry/helper/src/main.rs and existing bounded build evidence.
The VM kernel, supervisor and worker are trusted; commands are not. The twelve
retained bits apply in the mapped owning user namespace, not initial-userns root.
This is an explicit role/constraint review, not proof that every bit is minimal
or that the complete default-Allow syscall policy is qualified.

Capability                  Intended build role and necessary boundary
--------------------------  ---------------------------------------------------
CHOWN                       Construct target UID/GID ownership; mapped filesystem
                            ownership semantics must preserve target values.
DAC_OVERRIDE                Root-like access to target files; detached root and
                            absence of outside directory/device FDs are critical.
FOWNER                      Modes, ACLs and metadata on target-owned files;
                            does not imply arbitrary supervisor-path access.
FSETID                      Preserve intended set-ID/group metadata when building;
                            executable privilege behavior still depends on NNP,
                            mount policy and exec credential rules.
KILL                        Manage own step services/processes. Private PID scope
                            and worker placement matter, not this bit alone.
SETGID, SETUID              Package/user-switching tools within mapped IDs. This
                            cannot grant unmapped initial-root identities.
SETPCAP                     Root-like capability management within permitted/
                            bounding constraints. Necessity is not isolated by a
                            per-capability distro workload test; see below.
NET_BIND_SERVICE            Low-port services in the command's private network.
                            Routing and socket-family policy are separate gates.
SYS_CHROOT                  Nested install-root tools; no outside directory FDs
                            and detached old root are prerequisites.
SYS_ADMIN                   Existing FUSE labeling comparison requires this bit
                            in the owning userns for security.selinux. Its broad
                            authority motivates the explicit mount/namespace/
                            tracing/key/kernel-interface restrictions and audits.
SETFCAP                     Construct target file-capability metadata; does not
                            qualify resulting executable privilege transitions.

Explicit limitations remain: MKNOD and LINUX_IMMUTABLE are not retained, and
mapped FUSE kernel rules also restrict device nodes, immutable/append flags and
trusted xattrs. These are area11 OS-image compatibility blockers, not implicitly
accepted feature omissions. NET_ADMIN/NET_RAW/SYS_PTRACE/DAC_READ_SEARCH and other
excluded bits are not restored merely because namespace UID0 retains SETPCAP.
Filesystem-specific export callbacks still matter (FILE-HANDLE-REVIEW.txt).

Self-transition validation:
Both restricted policy steps start with exactly the declared bounding/effective/
permitted masks, empty ambient/inheritable and NNP. Valid capset requests attempt
to add each of two absent bits (SYS_PTRACE and LINUX_IMMUTABLE) to effective,
permitted and inheritable sets separately. All six fail EPERM and byte-for-byte
capget data stays unchanged. Bounding queries confirm absence. Ambient raise of
each bit fails EPERM and remains unset. No other process is targeted, no absent
capability is used, and no identity or namespace changes occur in this probe.
Pinned security/commoncap.c cap_capset enforces permitted/effective/inheritable
subset bounds; ambient raise requires permitted+inheritable membership. Sources
and hashes are retained in reproduced/capability-transition-source.

Do not overstate entry invariants:
Empty ambient/inheritable sets are entry conditions, not a promise that commands
cannot later populate them with retained permitted bits. The test concerns two
excluded bits, not every possible credential/exec sequence. Full setuid/exec,
worker UID reuse and immutable runtime closure remain separate gates. Keeping
SETPCAP is not demonstrated to be necessary for every workload; neither is its
removal validated as compatible with the requested root-like build experience.
No policy change is selected by this review.
