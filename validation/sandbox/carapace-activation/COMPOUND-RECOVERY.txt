Compound snapshot dependency recovery candidate
===============================================
Reproduce:
 python3 validation/sandbox/carapace-activation/build.py --death-probe --recover-incomplete --out NEW-BUILD
 python3 validation/sandbox/guest.py carapace-activation-recovery \
   --kernel-version 7.2.10-200.fc44.x86_64 --activation-tests-build NEW-BUILD \
   --out NEW-GUEST --run
Evidence: reproduced/carapace-compound-recovery. Guest exit0 at1.57s.
The same candidate patch is applied only to a copied pinned carapace dependency.
No parent repository/cache source or production dependency was modified.

The new safe-Rust test builds two tiny real persistent snapshot stores using
carapace::image::Planned, rather than inventing a mock table or corrupting a disk.
Both logical ranges are8KiB. The lower store changes block0 to0x41; block1 falls
through to the zero origin. The upper store changes block1 to0x62. Loop inputs
are read-only/autoclear. The lower snapshot is an independently retained reader.

For each Created/Loaded/Resumed/Opened boundary:
- A distinct owned child process activates the upper snapshot over that live
  lower snapshot, then waits at the selected bounded test gate.
- Parent kills/reaps only that child. The lower reader still returns0x41/zero.
- Ordinary candidate activation recovers/reuses the upper mapping. The parent's
  upper-COW loop handle closes; the active snapshot table is its remaining
  device-lifetime anchor. Reading upper returns0x41/0x62.
- Lower device identity is unchanged. Closing upper allows its mapping to
  disappear; lower remains readable. Both COW files remain byte-identical.
- After all four cases, closing the independent lower reader releases lower and
  zero mappings. Guest requires no remaining DM mappings or attached loops.

All earlier zero-target death, rollback/locking/reuse, held-inactive, conflicting-
active and interrupted-recovery tests pass in the same guest. No manual DM/loop
removal occurs between the interrupted upper activation and recovery or as the
passing cleanup path. The matrix is bounded by child gates and teardown waits.

Scope: actual snapshot dependency retention through activation death/recovery,
with a held shared lower reader. This is not a full verity chain crash matrix,
simultaneous independent upper creators, every recovery instruction boundary,
privileged noncooperating device-management races or adopted recovery protocol.
Earlier authenticated-chain tests provide separate verity evidence. The candidate
still relies on the same publication lock and fails when an inactive mapping is
open; it does not authorize generic orphan deletion from numeric IDs.

This closes the previously untested compound-COW/shared-reader case. Maintained
API/patch adoption and selected executor/coordinator integration remain open.
The mapped-FUSE semantic blocker and reserved-identity protocol are unaffected.
