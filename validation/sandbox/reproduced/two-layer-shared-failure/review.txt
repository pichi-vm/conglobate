Two-layer shared-block concurrency — 2026-10-21
==============================================
The existing chain-shared-block and chain-shared-block-failure cases now prepare
an ext4 base plus one genuine sealed snapshot layer containing /shared-layer.
Four read-only loops supply the data/hash pairs. Each build authenticates both
layers before independently assembling the same block-backed chain. At overlap,
DM tables contain two writable snapshots with the same origin, exactly two base
snapshots, two verity mappings and one zero mapping.

Success: both independent outputs restage, pass fsck, remount under kernel ext4,
preserve the second-layer file and publish matching inventories. A completes
while B stays active. Failure: A's controlled command failure has no published
output; B completes the same checks. All four shared input files remain unchanged;
all DM mappings and attached loops are released. Both guests exit0. Commands
receive the restricted FUSE view, not the block handles. Source snapshots retained.
The inventory checker now asserts the entire inherited prefix and its top root;
the previous single-layer assumption was a diagnostic assertion, not a production
inventory bug. Production code was not changed by this extension.

Negative evidence retained: preparation without explicit type (v1), with explicit
ext4 (v3), and with kernel log (v4). The kernel reports bad block size1024.
Pinned fs/ext4/super.c calls sb_set_blocksize; block/bdev.c rejects a size below
the block device's logical block size. These are source corroboration, not exact
Fedora build-source identity. The fixture now formats ext4 with4096-byte blocks.
This is a real compatibility constraint: successful FUSE operations on a1KiB
filesystem do not prove that filesystem is kernel-mountable on the assembled
4KiB device. No silent filesystem conversion or compatibility waiver is proposed.
The v5 run reached filesystem verification but failed the old inherited-prefix
assertion. The separate v2 packaging failure never started a guest. A failure-case
packaging attempt likewise hit EDQUOT before runtime; cleaned generated files.

Reproduce with README's two existing commands. The first historical README
section describes retained single-layer evidence; current cases use two layers.
Limits: two builds, two inherited layers, controlled command failure; same mapped
UID range, not cross-build credential isolation. No simultaneous activation death,
final-executor qualification, allocator proof or fix for the pre-resume defect.
This closes the missing bounded multi-layer shared-block concurrency check in18.
