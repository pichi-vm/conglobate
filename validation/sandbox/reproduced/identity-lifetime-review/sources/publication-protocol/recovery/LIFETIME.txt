Recovery lease versus namespace completion — 2026-10-21
=======================================================
Source review plus a bounded disposable-guest process test. No production change.

Pinned upstream source (not a claim of exact Fedora source identity):
linux f47d223627f80cb7a1eb14c585fe6cb35de5e984 kernel/exit.c do_exit calls
exit_files before exit_notify. exit_notify invokes forget_original_parent, which
calls find_child_reaper; the last namespace-init thread invokes
zap_pid_ns_processes. In kernel/pid_namespace.c, that operation disables PID
allocation, signals remaining tasks, reaps children and waits for outside-parent
zombies to disappear before permitting init to finish. URLs/hashes and complete
files are retained in reproduced/recovery-lifetime-source.

Consequence: file closure/lease release is earlier than namespace completion.
Moving a lease into namespace init does not by itself turn lock acquisition into
proof that namespace teardown has finished. The publication-phase lease tested
previously is valid for mutual exclusion, not a complete build-writer barrier.

lifetime.py runtime control:
- Create one owned PID namespace in the disposable guest; its single-threaded
  init holds an exclusive lease and otherwise waits.
- A trusted parent outside that namespace places its next child inside using
  setns(CLONE_NEWPID). That child immediately exits; its parent deliberately
  defers reaping. The child is a zombie, not a writer or running command.
- Kill namespace init using a previously pinned pidfd. Its lease becomes
  acquirable, while its pidfd remains nonterminal because namespace shutdown
  waits for the outside parent's zombie. An owned staging sentinel stays intact.
- A candidate conjunction of lease ownership AND terminal namespace-init pidfd
  defers cleanup at that point. The test performs no actual deletion.
- Reap the owned zombie. Namespace init now becomes terminal and is reaped;
  lease identity/data remain intact and all fixture processes are accounted for.

This deterministically validates the ordering gap without timing a live writer
race, invoking ptrace, affecting another workload or relying on a stuck kernel
operation. It does not demonstrate a surviving writer after lock release: the
controlled delay is an already-exited child. Nor does it integrate the barrier
with the real filesystem worker, storage cleanup or orphan collection. The
existing full artifact recovery matrix runs before this isolated lifecycle test.

Requirements for eventual recovery:
Retain trusted lifetime evidence independently of the lease; a pinned namespace-
init pidfd and established containment can provide a barrier for this topology.
Do not reopen a numeric PID and assume it identifies the old namespace after
reuse. If all holders of authoritative lifetime handles die, disk records and
an acquirable lease alone cannot establish that barrier; retain Unknown until a
separately validated mechanism establishes quiescence. No new daemon, cgroup
requirement, workload restriction or external runtime is adopted here.
