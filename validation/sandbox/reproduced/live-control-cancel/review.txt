Live coordinator socket exclusion in composed builds
====================================================
Reproduce both chain-build-admission and chain-build-cancel:
 python3 validation/sandbox/guest.py CASE --kernel-version 7.2.10-200.fc44.x86_64 \
   --worker-build /tmp/conglobate-finalize-workers --out NEW-DIRECTORY --run
Retained results: reproduced/live-control-success and live-control-cancel.
Both guest exit0, including existing completion/publication/cancellation checks.

The earlier SCM_RIGHTS fixture exercised only command-local sockets. This test
adds a live trusted peer to the actual build composition, without sending recipe
messages to a trusted control interface. admission.py starts the arbiter in
root-owned mode0700 /work/admission-control, confirms status=Building, and only
then starts the actual Chain/Snapshot/FUSE/restricted-command build.

A small safe Rust helper runs inside the recipe after restriction assertions.
It attempts UnixStream::connect to four fixed owned-fixture paths:
 /work/admission-control/control.sock
 /.old/work/admission-control/control.sock
 /proc/1/root/work/admission-control/control.sock
 /proc/self/root/work/admission-control/control.sock
Every attempt must return NotFound; permission denial, connection refusal or a
successful connection fails the fixture. No bytes/operations are sent on any
unexpected successful connection. The helper checks ordinary pathname reachability,
not vulnerabilities in the kernel or socket implementation.

The command then enters the existing bounded rendezvous. Trusted coordinator
again receives Building from the still-live socket and rejects premature reserve/
commit. Thus an absent listener cannot explain the command's negative result.
Existing command-local Unix/SCM_RIGHTS tests establish that the candidate policy
does not simply deny every connect operation. Existing inherited-FD controls
remain separate and necessary; pathname checks alone cannot exclude leaked FDs.

Success case: command finishes, worker/storage/namespace completion gates pass,
then trusted prepare/reserve/commit publishes the exact completed artifact.
Cancel case: trusted cancel is accepted while command is live; command is allowed
to finish, but prepare/reserve/commit stay Cancelled and public output is absent.
The new helper is diagnostic code installed in this fixed fixture root; this is
not a change to production image contents or a generic recipe implementation.
Other coordinator-death fixtures keep their original command mapping unchanged.

Scope: this selected coordinator topology and four paths during a live build.
Private network namespaces alone are not the pathname-socket boundary. Protected
placement outside command roots, root pivot/detachment, PID/proc visibility and
FD admission are the relevant controls. No claim covers arbitrary additional
trusted endpoints, all possible pathname aliases, client resource exhaustion,
control-protocol authentication, final runtime selection or all syscall policy.
The original post-build-only socket review gap now has this live composition
evidence. Identity reuse, backend metadata and final executor adoption remain
separate gates; this does not change their status.
