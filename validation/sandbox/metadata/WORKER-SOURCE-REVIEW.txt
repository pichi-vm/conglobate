Source explanation of birth-time and capacity observations — 2026-10-21
======================================================================
Four exact worker/library source files match the hashes in the version5 paired
build catalog used by the recent metadata experiments. Copies and original
catalog retained. This is inspection of the tested implementation, not a claim
about every FUSE version or the latest upstream worker.

Birth time
----------
fuse2fs.c stat_inode returns struct stat containing atime, mtime and ctime.
fs_ops registers op_getattr but no statx callback. Creation separately writes
i_crtime through EXT4_EINODE_SET_XTIME. This accounts for the distinction observed
in automatic-timestamps: disk birth time exists, build-side STATX_BTIME is absent.
The tested libfuse include/fuse.h does offer the high-level statx callback and
lib/fuse_lowlevel.c offers fuse_reply_statx. lib/fuse.c fuse_fs_statx dispatches
the callback when present and otherwise returns ENOSYS. Thus a worker-side
statx implementation is a concrete correction path; no general FUSE protocol
inability has been demonstrated. No correction has been implemented or tested.

A correct implementation must resolve the inode under the existing worker lock,
return supported BASIC_STATS fields consistently, decode extended i_crtime only
when it fits the inode, and set the returned mask honestly. The API also allows
fi to be null and path to be null with AT_EMPTY_PATH; copying path-only getattr
logic would not cover the full interface. Open-file, symlink and missing-path
behavior require tests before calling such a patch complete. These are proposed
acceptance criteria for a fix, not additions that supersede the21-area checklist.
A fix here would not remove host initial-userns gates on privileged metadata.

ENOSPC capacity
---------------
fuse2fs.c fs_can_allocate reserves filesystem blocks from all callers unless
alloc_all_blocks is explicitly set. With a zero configured reserve it instead
reserves one tenth of total blocks. Its source comment explains this as protection
against libext2fs corruption at complete exhaustion. The write path calls the
gate using the requested write length rounded to filesystem blocks and returns
ENOSPC if refused. This corroborates earlier rejection as deliberate worker
policy; it does not numerically derive the exact observed2MiB difference or prove
that every allocation/corruption case is safe. No reserve setting changed.

Conclusions
-----------
Birth-time visibility is a worker API omission with an available library path.
Earlier ENOSPC is consistent with an explicit protective allocation policy.
Neither result justifies weakening filesystem correctness requirements, disabling
the reserve, selecting a backend, or asserting a maintained implementation fix.
Area11 remains incomplete; this source review resolves classification ambiguity.
