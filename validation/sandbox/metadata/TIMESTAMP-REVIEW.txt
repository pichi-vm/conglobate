Automatic timestamp fidelity and birth-time visibility — 2026-10-21 UTC
======================================================================
Reproduction: guest.py metadata --kernel-version7.2.10-200.fc44.x86_64 (space
between option and value) --worker-build /tmp/conglobate-finalize-workers
--protocol-worker-build /tmp/conglobate-acl-protocol-v5 --out NEW --run.
The existing six-case matrix covers kernel ext4, initial-userns FUSE and mapped
FUSE, each with and without metadata_csum. Worker/library input hashes are in
inputs.json. All storage is an owned disposable guest image; no host share/NIC.

The new probe creates one ordinary file, writes and fsyncs it, chmods it,
renames it and reads it after deliberately setting an old atime. Bounded1.1s
intervals separate write/chmod/rename so coarse timestamp granularity cannot
accidentally conceal the transition. Linux statx is called through libc with
AT_STATX_FORCE_SYNC and explicit returned-mask handling. Unsupported birth time
is not interpreted as zero or a successful comparison. This is native x86_64
ABI validation, not portability qualification.

Results: all54 automatic-update checks pass across six cases: write updates
mtime/ctime; chmod and rename update ctime while preserving mtime; read updates
stale atime while preserving mtime/ctime. Kernel birth time remains unchanged
through all operations in both reference cases. All fields visible during the
build persist exactly after unmount, fsck and kernel read-only remount.

Limitation: none of the four FUSE cases exposes STATX_BTIME, while the kernel
remount does. The persisted birth time is positive and no later than the final
mtime. This demonstrates disk presence, not that birth time was stable throughout
the FUSE operations: the build-side API never supplied it for comparison.
Tools that depend on reading birth time during the build cannot assume parity.
No claim about birth-time setters (none tested), lazytime/noatime variants,
concurrent timestamp races, symlink automatic updates, crash durability or final
command policy. Previous explicitly-set symlink timestamps remain separate.

The retained run source predates the standalone result validator. The current
validator was executed against its saved log, checking all six observations and
exact persistence, plus negative missing-record/false-operation controls. The
runner now invokes it on future metadata cases. Source catalogs retain the actual
executed source; timestamps-with-validator.py retains the later validator.
An accidental extra CASES entry for the unrelated acl-fix case was corrected
before final harness checks; no acl-fix run was attempted in this turn.

This closes the previously untested bounded automatic file-timestamp semantics
and records birth-time visibility as a limitation. It does not close area11's
ACL maintenance, privileged metadata, extent-operation or broader workload gaps.
