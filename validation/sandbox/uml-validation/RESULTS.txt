UML sandbox validation — completed 2026-10-21

Verdict: the tested UML composition is functionally feasible. All14 bounded
validation areas have executed evidence against the criteria in MATRIX.json.
This completes validation, not acceptance or implementation of a production
sandbox. The packaged kernel's single CPU and substantial workload overhead are
material design tradeoffs. No production conglobate source was changed in this
goal; preexisting user changes are preserved.

Trust model
The entire UML kernel, initramfs and command process tree is untrusted. The outer
Linux kernel and conglobate supervisor are trusted. Inner root may control its
own guest completely. Outer identity, namespaces, capabilities, seccomp, cgroup,
network policy and explicit block-device access enforce isolation. Console text,
mconsole replies and exit status cannot establish semantic recipe correctness
or authorize inventory publication. BOUNDARY-REVIEW.txt explains these boundaries.

Validated results
- Packaged Debian UML6.12.101 supports native ext4/XFS/Btrfs. Required OS metadata
  survives independent remount/checks: IDs, modes, ACLs, capabilities, devices,
  links, sparse allocation, inode flags and user/trusted/foreign SELinux xattrs.
- A Fedora root labeled with UML's active LSM=capability boots its own SELinux
  policy enforcing. The build VM need not run the target policy.
- Actual authenticated carapace -> conglobate Snapshot -> UML writes -> sealed
  scute independently boots through corium. Base bytes remain unchanged. Real
  snapshot command failure/timeout after writes rejects export and cleans the
  cgroup, runtime, dm and loop stacks. SELinux and scute boots are separate tests.
- Bounded confinement, inherited-resource, resource-pressure, concurrency and
  recovery probes pass. Recovery assumes a surviving trusted coordinator with
  retained handles; cgroup death is checked before acceptance, not inferred from
  a launcher exit or sampled PID list.
- Private network/TAP/NAT tests pass for UDP/TCP DNS, A/AAAA, search, NXDOMAIN,
  fixture IPv4/IPv6 egress, public IPv4 egress, disabled networking, resolver
  restoration, unsolicited input rejection and owned supervisor service exclusion.
- All four distros complete representative bootstrap, image changes, firmware
  preparation and independent native boot. Fresh disconnected steps verify
  persistence. Alpine/Debian/Fedora use diagnostic PID1; NixOS starts its real
  systemd system and validation unit. This is not comprehensive service health.
- All original distro roots and the final derived Fedora root pass confined
  read-only e2fsck and clean-state checks. Final boot hashes stay unchanged.
  All four final boots have no kernel panic and explicitly power off.
- Existing artifact/inventory tests pass8/8, including deterministic CBOR, strict
  decode, invalid/mismatched output, partial I/O, cancellation and publication races.

Debian's packaged configuration has CONFIG_NR_CPUS=1. Native comparisons use
2vCPU; UML runs one guest CPU inside the same2vCPU VM. Kernel versions differ and
other validation work overlapped. These are observed feasibility costs, not a
precisely isolated mediation-overhead estimate. Near-native single-threaded CPU
loops do not establish parallel compiler performance. Full kernel compilation and
a newer/custom SMP UML kernel were not qualified. Dracut's slow interval included
lsinitrd/file-list processing; small zstd single/multithread probes all passed.

Runtime requirements discovered
Provide ordinary /proc, /sys, device nodes, descriptor symlinks and appropriate
PTY mounts. Bare devtmpfs lacks /dev/fd; Fedora bash process substitution needs it.
Nix needs devpts and switch_root onto a normal filesystem before sandbox
pivot_root. Disable unwanted pagers for batch diagnostics. Firmware tools need
explicit target kernel/drivers: uname/config describe UML, not the output kernel.

An ordinary truncated ext4 image crashes dumpe2fs. Confined checking fails closed;
do not parse or mount command-controlled filesystems in the trusted process or
outer kernel. A checker pass says only that its consistency checks passed.

Failures and audit corrections are retained, not counted as passes. Fedora's
initial600s deadlines were too short. Its first native diagnostic boot passed root
checks then panicked because the test renamed BusyBox incorrectly; its original
false-positive result is preserved alongside the corrected failure adjudication.
The final derived probe fixes argv0 and cleanly powers off. Stronger shutdown
checks also pass against the other three existing boot logs.

Design readiness and limits
Proceed to a design document if these costs are acceptable. Preserve the outer
trust boundary, protected inventory, immutable measured runtime inputs, explicit
block-device authority, no context checkout mount, bounded private scratch and
post-quiescence publication gate. The final syscall policy, runtime integration,
UID/resource lifetime and deployment prerequisites still require implementation
and review. These probes do not certify the existing production executor.
Actual host VPN/split-DNS integration, simultaneous loss of every trusted recovery
coordinator and hardware attestation are not claimed. The tested local topology
and retained-coordinator recovery have explicit evidence; no unlimited failure
combination or universal kernel-security claim follows.
