UML outer-boundary review (validation candidate, not production implementation)

Trust: the complete UML process tree is untrusted, including the kernel and
runner. Inner root, modules, hostfs, management sockets, guest console messages,
shutdown, and exit status provide no integrity boundary against a recipe. Trusted
conglobate owns input selection, device construction, confinement, teardown,
artifact hashing and inventory publication. The outer Linux kernel is trusted.

Reviewed source snapshot: Linux stable v6.12.101 files and source hashes under
../reproduced/uml-interface-review. Debian packaged configuration/kernel identity
are recorded separately. This is interface analysis, not an exhaustive kernel
vulnerability audit or proof that the distribution has no additional patches.

Hostfs uses ordinary host open/stat/directory operations. It therefore exposes
whatever the outer process can access. The namespace fixture has only explicit
read-only inputs, one writable snapshot, private scratch and scoped devices;
no build context checkout, supervisor cwd/home, inventory directory or cache.
Tests verify an owned hidden sentinel, read-only allowed input and namespace
view. Disabling hostfs in a custom kernel would reduce accidental exposure but
cannot replace the outer boundary because we already distrust the entire UML.

UML's helper.c uses clone/exec and inherits process confinement. No privileged
helper executable or host PATH is made available. Preventing exec alone is not
our security boundary. Existing native fixtures exercise arbitrary ordinary
process activity under the same restrictions, without assuming a well-behaved UML.

Mconsole creates a pathname Unix socket under UML runtime. Runtime is per-step,
mode0700, owned by that step identity; no supervisor control socket is exposed.
No mconsole notify address is supplied. Management responses are untrusted. A
recipe controlling its own UML via that socket only controls its own step. Host
pathname and abstract Unix supervisor endpoints were tested independently;
abstract Unix isolation requires a private outer network namespace.

UML UBD opens the granted device and performs host I/O. Guest block ioctls are
not a general trusted supervisor RPC. A compromised UML can nevertheless issue
any host syscall permitted to its own device handles: authorization must cover
the whole snapshot device, not just expected filesystem writes. The real
conglobate snapshot uses Discard::Disabled (src/snapshot.rs); origin assembled
read-only. Actual snapshot mutation/sealing and independent two-scute boot passed
with base bytes unchanged. No shared origin, whole-host disk, dm control device,
loop-control or supervisor mount is exposed to commands. Output must be quiescent
before trusted sealing; filesystem flush requests alone are insufficient.

UML requires ptrace for its own tasks. Candidate filter permits it; private PID
namespace/proc, dedicated outer identity and zero capabilities restrict its reach.
Do not rely on Yama or on the guest kernel protecting itself. No supervisor
process, proc directory or pidfd is inherited. Filter denies pidfd_getfd,
namespace creation/join, host mount API, keyring, BPF/perf, modules, reboot, swap,
io_uring and x32. clone3 returns ENOSYS for libc fallback; ordinary clone/fork
remain possible and are bounded by cgroup pids.max. This is a denylist candidate,
not a completed production allowlist; updates to the outer kernel need review.

The TAP is created by the trusted outer setup in a private network namespace,
owned by the step identity. /dev/net/tun is explicitly granted; outer capabilities
are dropped. NAT/filtering and DNS setup are outside UML's authority. Tests cover
positive egress plus disabled mode, resolver behavior, inbound rejection and
owned supervisor service exclusion. Guest root can change guest routes/DNS; that
cannot bypass the outer network policy. Real VPN/split-DNS deployment remains an
integration concern distinct from the tested local routed/DNS topology.

All descendants enter the bounded cgroup before launch. cgroup.kill plus a retained
group handle and populated=0 is the teardown authority. PID sampling is only
diagnostic. Recovery tests require a surviving trusted coordinator with a retained
handle and exclusive lease; simultaneous death of every trusted coordinator is
not a tested durable recovery mechanism. RAM-backed workspace disappears with
its owning build VM. Publication must not proceed on interrupted state.

Output checker finding: ordinary truncation of an owned ext4 fixture caused
Fedora dumpe2fs to segfault. Separately confined read-only checker failed closed;
e2fsck returned8. An unclean fixture can pass e2fsck -fn, so the prototype also
checks the filesystem's clean-state field. This is validation policy, not yet a
production requirement to run fsck on every output. Never mount or parse an
untrusted filesystem in the supervisor kernel. A checker exit0 establishes only
its defined consistency checks; it does not establish truthful build contents.

All8 existing artifact/inventory tests passed (cargo test --test artifacts),
covering deterministic CBOR/strict decode, unfinished/corrupt/mismatched output,
self-contained export, bounded stream reads, partial I/O failure, publication
cancellation and destination race. These qualify existing trusted publication
code separately; they do not imply production UML integration already exists.

Attestation claim must be precise: measured inputs were supplied to this confined
execution and the supervisor observed/hash-bound these outputs. An untrusted
recipe can deliberately produce arbitrary output or lie about completion. This
design cannot attest semantic correctness of the recipe's actions. Console text
must be bounded and treated as data; it cannot set inventory or publication state.

Runtime ABI findings from distro validation:
- Provide /proc, /sys, devtmpfs, standard /dev/fd/stdin/stdout/stderr symlinks,
  and devpts where commands need PTYs. Bare devtmpfs is not a complete /dev.
- Nix sandbox pivot_root needs a normal mounted root after switch_root; initial
  rootfs is insufficient. This transition occurs entirely inside untrusted UML.
- Batch commands must not accidentally inherit a terminal environment that starts
  pagers. Nix query diagnostic now redirects output and disables paging.
- Commands see the UML kernel version/configuration, not the eventual target
  kernel. Firmware tools must receive the intended kernel version and drivers.
  Fedora dracut's microcode and logging warnings illustrate environment-sensitive
  defaults; independent target boots validate the particular artifacts produced.
These are runner/recipe requirements. They do not enlarge the trusted boundary.

Packaged-kernel CPU limitation: retained Debian6.12.101 kernel.config has
CONFIG_NR_CPUS=1. Native comparison VM has2vCPU; UML runs one guest CPU inside
that same2vCPU VM. Measurements therefore include the packaged runtime's loss of
parallelism and kernel-version difference, not pure syscall mediation overhead.
Near-native single-threaded CPU-loop time must not be generalized to parallel
kernel compilation. Full kernel source compilation and a newer/custom SMP UML
kernel are not qualified by this run. This is a material selection tradeoff.
